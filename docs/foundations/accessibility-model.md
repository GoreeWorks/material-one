# Material One Accessibility Model

## Purpose

Accessibility is a system capability in Material One, not an optional component feature.

## Accessibility Signals

The adaptive engine considers:

- text scaling
- contrast preference
- reduced motion
- reduced transparency
- input capability
- assistive technology needs

## Design Requirements

Every component must provide:

- keyboard operation
- visible focus
- semantic structure
- screen reader meaning
- non-color communication
- scalable content behavior

## Adaptive Accessibility

Accessibility preferences modify behavior while preserving task completion and information hierarchy.

Examples:

- increased target sizes
- stronger contrast
- simplified motion
- preserved labels
- expanded readable layouts

## Validation

Accessibility validation should be part of component and system CI.
